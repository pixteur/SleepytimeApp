# Internationalization (i18n) & Localization

Two separate concerns — keep them distinct:

1. **UI strings** — buttons, labels, settings. Must be externalized from day one.
2. **Story language** — the language the AI *generates* and the voice *reads*. Driven by the child's `language` setting.

## Launch languages

- **English (en)**, **French (fr)**, **Spanish (es)** — full support at launch.
- **Japanese (ja)** and others — framework built to support them; ship as content/voice coverage is verified.

## UI strings

- Use Flutter's built-in localization (`flutter_localizations` + ARB files) with generated `AppLocalizations`.
- **Rule: no hardcoded user-facing strings.** Everything goes through `l10n`. Enforced in review.
- Files: `lib/l10n/app_en.arb`, `app_fr.arb`, `app_es.arb`, `app_ja.arb`, …
- Handle plurals, gender, and date/number formatting via ARB placeholders.
- Locale resolves from the active child's `language`, falling back to device locale, then `en`.

## Story language (generation)

- `PromptBuilder` injects the target language: "Write the story in {language}, natural for a {age}-year-old native speaker."
- The structured metadata (summary, character notes, threads) should be stored in the **story language** so continuity context matches what the model sees next time. (Optionally keep an English mirror summary for debugging.)
- Cultural appropriateness: a story for a Japanese-speaking child shouldn't just be a translation — let the model localize names, foods, settings naturally. Note any culture-specific safety considerations per locale.

## Bilingual mode (a modifier on any story)

A standout feature: **Bilingual mode** generates a *bilingual* story so a child absorbs a second language through the bedtime ritual. It is **not a theme** — it's a modifier that layers onto *any* theme (a bilingual Adventure, a bilingual Documentary, …). Distinct from the UI/story-language settings above.

- Driven by `Series.bilingualEnabled` + `secondaryLanguage` + `bilingualBlend` (see [data-model.md](data-model.md)).
- **Blend levels** (parent-set, can step up as the kid progresses):
  - `sprinkle` — mostly the primary language with a few 2nd-language words (often with a gentle inline gloss the first time).
  - `phrases` — whole phrases/sentences in the 2nd language, surrounded by primary-language context.
  - `alternating` — balanced; e.g. one character speaks each language, or lines alternate.
- `PromptBuilder` instructs the model to keep the 2nd language **natural, correct, and age-appropriate**, to make meaning recoverable from context (don't frustrate the child), and to tag which spans are in which language in the structured output.
- The language spans drive **voice switching** during narration — see [voice-tts.md](voice-tts.md).
- Great pairing with the **Around the World** / **Learning** themes; also a natural fit for households already raising kids bilingually.

## Voice / TTS language

- Voice list filtered by language; some languages lack on-device voices (esp. Japanese, less-common locales) → fall back to a cloud TTS provider. See [voice-tts.md](voice-tts.md).

## RTL & scripts

- No RTL languages at launch, but don't hardcode `LTR` assumptions in layouts — use directionality-aware widgets so Arabic/Hebrew can be added later.
- Ensure fonts cover CJK (Japanese) glyphs — bundle or verify a font with broad coverage (e.g. Noto Sans / Noto Sans JP).

## Testing

- Pseudo-localization pass to catch hardcoded strings and overflow.
- A smoke test per launch language: create a profile in that language, generate one beat, confirm UI + story + a voice are all in-language.

## Phasing

UI externalization starts in **Phase 0/1** (cheap if done early, painful if retrofitted). Full fr/es content + Japanese framework in **Phase 4**. See [build-plan/phase-4-i18n-theming.md](../build-plan/phase-4-i18n-theming.md).
